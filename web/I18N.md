# Internationalisation (FR/EN)

The console ships two complete interfaces. English is the source of truth;
French is a first-class translation, written for an operator reading an error
under stress, not a literal rendering of the English.

## Moving parts

| File | Role |
| --- | --- |
| `src/lib/i18n.tsx` | `I18nProvider`, `useI18n()` → `{ t, lang, setLang }`, language detection, persistence, `translator(lang)` for non-React helpers. |
| `src/locales/en.ts` | English dictionary, flat `Record<string, string>`, keys grouped by area. |
| `src/locales/fr.ts` | French dictionary, same key set (enforced by the check script). |
| `src/api/errors.ts` | `apiErrorMessage(error, t)`: maps `error.code` to `errors.<code>`, falls back to the server message, then `errors.unknown`. |
| `src/components/language-toggle.tsx` | EN/FR control in the app shell (desktop sidebar and mobile drawer) and on the sign-in screen. |
| `scripts/check-i18n.mjs` | Gate: finds hardcoded copy and dictionary drift. |

## Language selection

`localStorage["fleett.lang"]` wins; otherwise `navigator.language` starting with
`fr` selects French, anything else English. Changing the language updates the
tree immediately (no reload), writes the preference, and sets
`document.documentElement.lang`. The choice survives reloads and is applied
before the first paint of the console.

## Adding copy

1. Add the key to **both** `src/locales/en.ts` and `src/locales/fr.ts`.
2. Call `t("area.key")` in the component. For hooks, `const { t } = useI18n()`.
3. Run `node scripts/check-i18n.mjs --strict`. It fails on missing keys,
   duplicates and hardcoded copy.

Interpolation uses named braces: `t("fleet.deletedId", { id })` against
`"Instance {id} deleted."`. Do not concatenate sentences around values; if the
word order differs, rewrite the sentence so the placeholder can move.

Plurals are explicit `…One` / `…Many` key pairs selected in code, never a
runtime `plural()` helper: French and English do not pluralise the same words.
A pair that carries a count interpolates `{count}` in both variants.

Copy that embeds a technical token wraps it in backticks and renders through
`<RichText text={t(...)} />`:

```ts
"skills.picker.hint": "Skills are mounted read-only at `/opt/data/skills/<name>`."
```

## API errors

Every server-driven code has an `errors.<code>` entry. `apiErrorMessage`:

1. uses the translated copy when the code is known;
2. keeps the controller's English message for an unknown code (new backend
   release, console not yet updated);
3. uses `errors.unknown` when there is no message at all.

Error surfaces (`ErrorAlert`, toasts, inline field errors, dialogs) all call
`apiErrorMessage(error, t)` — never `error.message` directly.

**A new backend error code ships with two translations.** Add
`errors.<code>` to both dictionaries in the same change as the code. If a code
deliberately keeps a dynamic server detail (for example `driver_error`, whose
compose stderr is shown under the translated lead-in), say so in a comment.

## What stays English

These are technical identifiers or machine content; translating them would make
them wrong:

- commands, flags, paths, URLs, environment variable names, model ids, image
  tags, container ids, commit hashes, log lines, CLI and API output;
- YAML/JSON/`compose.yaml` content, code samples, file paths and API field
  names;
- template descriptions and doctor check details supplied by the controller
  (host data, English by convention);
- YAML pipeline parser messages, which quote field names and offsets;
- persona `SOUL.md`, `SKILL.md`, assistant prompts and assistant context
  payloads (model-facing text);
- protocol enums that are also API values (`rw`/`ro`, namespaces
  `global`/`shared`/`instance:<id>`, role ids `admin`/`viewer` in audit rows).

A short allowlist in `scripts/check-i18n.mjs` names the UI-visible technical
literals (`Esc`, `Regex`, `Cron`, `ls /opt/data`, security header names). Add an
entry only with a reason.

## Deliberate minor exception

`components/ui/dialog.tsx` and `components/ui/sheet.tsx` are otherwise
untouched shadcn files, but their screen-reader-only close label is app copy:
it now renders `t("common.close")`. No visual or behavioural change.

## Verification

```sh
pnpm exec tsc --noEmit
pnpm build
node scripts/check-i18n.mjs          # copy + drift report
node scripts/check-i18n.mjs --strict # fails on dictionary drift too
```

Manual pass: switch EN/FR on the sign-in screen and in the shell, visit every
page, open a destructive dialog, trigger a refused API call (provider in use,
invalid token) and confirm the French message; then check that an unknown code
falls back to the English server message.
